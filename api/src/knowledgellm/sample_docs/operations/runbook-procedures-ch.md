# Northstar 維運部 — 事件管理維運手冊

> 供公開展示使用的虛構範例；並非真實公司資料或政策。

## 1. 目的與事件分類
本手冊定義調查、控制及解決 Northstar 各平台服務中斷的標準作業程序。

### 嚴重程度定義：
- **P1（重大中斷）**：服務完全中斷、關鍵資料管線故障或對客戶造成重大影響。
  - 確認回應 SLA：**10 分鐘**內。
  - 更新頻率：每 **30 分鐘**發布狀態更新。
- **P2（效能下降）**：部分功能受損、高延遲或不造成阻斷的錯誤率激增。
  - 確認回應 SLA：**30 分鐘**內。
  - 更新頻率：每 **60 分鐘**發布狀態更新。
- **P3（輕微問題）**：非緊急系統異常或影響較小的內部工具異常。
  - 確認回應 SLA：**4 個工作小時**內。

## 2. 值班升級處理矩陣
1. **主要值班工程師**：第一線應變人員；評估警示、驗證日誌並宣布事件嚴重程度。
2. **次要待命人員**：協調跨團隊除錯及事件溝通。
3. **維運協調員**：管理狀態頁面溝通及客戶支援警示。
4. **工程主管**：若處置超過 45 分鐘且尚未找出明確根本原因，則為升級聯絡人。

## 3. 事件後檢討（PIR）
- 事件解決後 **72 小時**內，須發布不究責的事件後檢討文件。
- 矯正行動項目須記錄於維運待辦清單，並指定負責人及目標完成日期。
